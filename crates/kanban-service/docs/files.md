# 文件与附件

文件由不可变 blob、文件对象和 `file.attachment` 关系组成。`file_begin_upload` 创建受控暂存，
`file_commit_upload` 在 service 写锁内校验内容并提交文件对象、关系和事件。内容块最大 64 KiB，
单文件最大 256 MiB，空文件有效；每个附件根目录最多接收四个暂存上传。

原任务附件接口适配此模型，保留附件 ID 和 DTO。文件可关联多个对象；删除任务附件只移除该
任务对应的关系，其他关联和 blob 保留。文件原名、内容类型、字节数和 hash 不可变，显示标题
可以作为对象属性编辑。相同内容可共享 blob，当前没有自动 blob GC。

上传 ID、文件 ID 和存储路径由不同边界管理：客户端只能提交文件身份和安全文件名，不能指定
任意本机路径。service 生成内容路径，读取时检查目录、符号链接、长度和 hash。旧数据的相对
路径只用于迁移与受控恢复。

取消或超时会释放未发布的暂存。内容先发布到不可覆盖的位置，再提交 canonical metadata；
提交结果未知时保留已发布内容。调用者应使用原文件 ID、actor 和完整上传参数查询或重放，
不能把超时解释成回滚，也不能自动更换 ID 重试。已经解除的关系不会因上传重放而复活。

旧 `task_attachments` 数据在同一迁移事务中转换，表保持为空并禁止新增。portable JSONL
只交换 metadata；恢复时必须同时恢复对应附件目录，不能把 metadata 导入成功解释成文件内容
已恢复。SQLite v30 导入器会校验并暂存附件内容。

长期取舍见 [统一文件对象](../../../docs/adr/0009_file_objects.md)。
