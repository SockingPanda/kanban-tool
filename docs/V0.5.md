# V0.5 Release Notes

V0.5 把文档包推进为可运行的本地 Kanban / durable work queue MVP。本文只描述当前已实现范围；完整长期 CLI 设计仍以 `docs/CLI_SPEC.md` 为目标，不等同于 V0.5 全量交付。

## 范围

已实现：

- Rust workspace：`kanban-core`、`kanban-sqlite`、`kanban-cli`。
- SQLite 初始化：`kanban init`、默认 board、默认 columns、schema migration。
- Task CRUD：`kanban task create/list/show/update/archive`；`task update` 支持 title、description、assignee/clear-assignee、priority、scheduled_at/clear-scheduled-at、due_at/clear-due-at、metadata、expected_lock_version。V0.5 CLI timestamp 字段（如 `scheduled_at`、`due_at`）使用 Unix epoch milliseconds。
- Event 记录：创建、更新、状态转换、依赖变更均写入 `task_events`；heartbeat 会写 `task.heartbeat` 事件。
- 状态机 MVP：promote、claim/start、heartbeat、done/complete、review、block、unblock、reclaim、archive。`complete` 是 `done` 的 CLI alias；V0.5 reclaim 支持 bare `kanban task reclaim` 和等价的 `kanban task reclaim --expired`，均只处理 expired claims，task-specific reclaim/force/to 仍不在 V0.5 范围内。
- Dependency MVP：add/remove/list、直接/间接环检测、依赖未完成时 ready child 降级、禁止给 running child 新增未完成 parent、parent 完成后 child promotion。
- Run / dispatcher MVP：`kanban dispatch --once` reclaim expired、promote due todo/scheduled、claim ready task、执行本地 command、heartbeat、写 run、写日志文件路径、按成功/失败策略收尾。
- CLI JSON：核心命令支持 `--json` 机器可读输出。

明确暂未进入 V0.5 / 不得在 V0.5 验收中声称已完成：

- 常驻 dispatcher loop 的服务化管理。
- Web API / Web UI / board 管理命令 / server。
- comments / attachments / labels CLI。
- doctor / backup / export。
- `kanban run logs` / `kanban run show`；V0.5 只提供 `kanban runs <task_ref>` 列出 run 元数据和 log_path。
- `kanban events watch`。

## 验证

> Historical note: the verification and smoke commands in this release note document historical release-gate evidence. For current development verification, follow AGENTS.md.

每个实现任务必须先通过 worker 自测，再交给独立 spec reviewer 和 quality reviewer；P0/P1 必须在同一分支修正后重新 review。最终合并前由父级执行完整验证和 CLI smoke。

最终验证要求：

```bash
cargo fmt --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

已跑 CLI smoke：

```bash
kanban --db /tmp/kb.db init --json
kanban --db /tmp/kb.db --json task create "v0.5 smoke" --description "run worker"
kanban --db /tmp/kb.db task list
kanban --db /tmp/kb.db --json dispatch --once --command 'echo smoke=$KB_TASK_ID'
kanban --db /tmp/kb.db --json task show <task_id>
kanban --db /tmp/kb.db runs <task_id>
```

结果：SQLite `PRAGMA integrity_check` 为 `ok`，smoke task 状态为 `done`。
