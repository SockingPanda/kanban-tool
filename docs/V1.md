# V1 Local Web API Release Notes

V1 adds a runnable localhost HTTP API on top of the same SQLite command service used by the `kb` CLI. It is API-first and intended for local scripts and a future local Web UI.

## Implemented scope

- `kanban-server` crate with Axum router construction via `build_router(AppState)`.
- `kb serve` command.
- SQLite-only storage and idempotent database initialization when serving.
- Localhost default bind: `127.0.0.1:8721`.
- JSON success envelope: `{ "data": ..., "meta": ... }`.
- JSON error envelope: `{ "error": { "code": ..., "message": ... } }`.
- Actor resolution for mutating HTTP routes: body `actor`, then `X-KB-Actor`, then server default actor.

## Serve command

```bash
kb serve
kb serve --host 127.0.0.1 --port 8721 --db /tmp/kb.db --actor local-dev
```

Defaults:

- Host: `127.0.0.1`
- Port: `8721`
- DB: the normal CLI default data path unless `--db` is provided
- Actor: OS username/default CLI actor unless `--actor` is provided

The default never binds a non-localhost interface. Passing a different `--host` is treated as an explicit user request.

## HTTP endpoints implemented

Health:

- `GET /health`

Boards and columns:

- `GET /api/v1/boards`
- `GET /api/v1/boards/{board}`
- `GET /api/v1/boards/{board}/columns`

Tasks:

- `GET /api/v1/boards/{board}/tasks`
- `POST /api/v1/boards/{board}/tasks`
- `GET /api/v1/tasks/{task_id}`
- `PATCH /api/v1/tasks/{task_id}`

Transitions:

- `POST /api/v1/tasks/{task_id}/transitions/specify`
- `POST /api/v1/tasks/{task_id}/transitions/promote`
- `POST /api/v1/tasks/{task_id}/transitions/claim`
- `POST /api/v1/tasks/{task_id}/transitions/reclaim`
- `POST /api/v1/tasks/{task_id}/transitions/heartbeat`
- `POST /api/v1/tasks/{task_id}/transitions/complete`
- `POST /api/v1/tasks/{task_id}/transitions/submit-review`
- `POST /api/v1/tasks/{task_id}/transitions/block`
- `POST /api/v1/tasks/{task_id}/transitions/unblock`
- `POST /api/v1/tasks/{task_id}/transitions/archive`

Dependencies, runs, and events:

- `GET /api/v1/tasks/{task_id}/dependencies`
- `POST /api/v1/tasks/{task_id}/dependencies`
- `DELETE /api/v1/tasks/{child_task_id}/dependencies/{parent_task_id}`
- `GET /api/v1/tasks/{task_id}/runs`
- `GET /api/v1/runs/{run_id}`
- `GET /api/v1/events?board=default&after=0&limit=100`
- `GET /api/v1/stream/events?board=default&after=0&limit=100`

## SSE event stream behavior

V1 implements `GET /api/v1/stream/events` as a finite snapshot stream. It reads matching rows from `task_events`, emits them as SSE frames, and closes the response.

Example frame:

```text
event: task.created
id: 123
data: {"id":123,"event_id":"e_...","task_id":"t_...","kind":"task.created","payload":{}}
```

Query behavior:

- `board` defaults to `default`.
- `after` defaults to `0` and returns events with DB id greater than `after`.
- `limit` defaults to `100` and is capped at `1000`.
- SSE `id` is the monotonic `task_events.id` database id.
- Invalid query parameters return the normal JSON error envelope before an SSE stream is opened.

Continuous polling/long-lived dispatch from this endpoint is intentionally deferred; clients that need updates in V1 should reconnect or periodically call `GET /api/v1/events`.

## Out of scope for V1

- Browser Web UI bundle, drag/drop frontend, or static asset server.
- Remote auth, users, RBAC, teams, tenants, or SaaS collaboration semantics.
- Labels, comments, and attachments APIs beyond explicit rejection/placeholder behavior.
- HTTP backup/export/checkpoint endpoints.
- Persistent dispatcher service supervision.
- A long-lived SSE dispatcher with blocking waits for future events.

## Smoke recipe

```bash
TMPDIR=$(mktemp -d)
DB="$TMPDIR/kb.db"

cargo run -p kanban-cli --bin kb -- --db "$DB" init
cargo run -p kanban-cli --bin kb -- --db "$DB" task create "smoke task" --description "ready spec"
cargo run -p kanban-cli --bin kb -- --db "$DB" serve --host 127.0.0.1 --port 8721
```

In another terminal:

```bash
curl -s http://127.0.0.1:8721/health
curl -s http://127.0.0.1:8721/api/v1/boards/default/tasks
curl -N http://127.0.0.1:8721/api/v1/stream/events?board=default\&after=0\&limit=10
```
