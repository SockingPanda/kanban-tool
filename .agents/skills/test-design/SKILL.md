# 测试设计与精简

## 目标与边界

用尽量少的必要环境、重复执行和维护负担，提供足够且可定位的行为证据。精简的是重复证明，
不是独有风险；允许删除冗余测试，也允许为缺失的边界增加测试，不设置条数配额或固定金字塔比例。

本 skill 负责测什么、在哪层测、哪些应合并或退出。命令与证据交给 `$check`，Rust 布局交给
`$style`，文档所有权交给 `$docs`。不另建测试框架、任务系统、全仓测试清单或自动 reviewer。
只执行已授权范围；用户只要求静态审核时不运行编译、产品测试或 benchmark。

## 先看实际证明，再改入口

先读当前 revision、受影响实现、测试正文、fixture helper 和 runner 配置；不要从测试名或历史
聊天推断当前覆盖。已有日志只说明其对应 revision、范围与环境，缺失日志不以估算补齐。

对要改的测试族回答四个问题，记录在本次任务或最终说明即可，不要求单独建文件：

1. **契约**：输入与前置状态是什么，可观察结果或不变量是什么？
2. **检错能力**：指出一个可信的错误实现，以及现有哪个断言会让它失败。
3. **独有边界**：相邻测试已经证明了什么，本测试额外证明了什么？
4. **成本**：真正需要到哪一层；建库、初始化、启动进程、样本规模和等待各发生几次？

若去掉关键操作、返回常量或错写字段仍能通过，先修断言。纯内部重构且现有契约足够时，可以不加
测试；修 bug 优先把最小反例并入已有契约，只有新的行为或故障边界才新建入口。

## 选择足够小的验证层

| 要证明的事 | 默认落点 | 不能借此声称 |
| --- | --- | --- |
| 状态转换、字段校验、排序规则 | owner 的纯函数／表驱动测试 | 已验证真实 SQL、持久化或并发 |
| DTO、fixture、编解码和字段映射 | 格式 owner；不建业务数据库 | 静态 JSON 来自真实 router，或已验证全部输入负例 |
| 唯一约束、事务、幂等、CAS、租约与重放 | 当前真实存储／service 的最小契约 | 内存 fake 等价于当前数据库引擎 |
| adapter 接线、状态码与错误映射 | 少量正式 router／客户端契约 | in-process router 覆盖真实 TCP、进程或浏览器 |
| 中断恢复、迁移、附件完整性、重启 | 独立且最小的真实故障场景 | 缩小样本后仍自动覆盖旧的页边界或中断点 |
| 冷启动、吞吐、内存与尾延迟 | 独立性能验收 | 正确性测试全绿即达到性能门槛 |

先核对当前依赖与持久化 owner，不把其他项目的 SQLite/Turso 方案代入本仓库。跨层多测仅在
增加新的边界证据时保留；不在每个 CLI/MCP/Web/Server 入口复制整份业务矩阵。

## 保留、下沉、合并与删除

同一行为的输入变体用具名表项表达；默认保留每项期望值和错误上下文，不写通用测试 DSL。
重复初始化同一完整流程，且流程内部已经检查全目录时，保留一次流程，不按字段或 producer /
consumer 名称重复启动。静态格式检查与真实流程拆开，真实流程不能因拆分而失去调用入口。

合并前逐项映射旧断言到新断言；需要新状态、不同故障注入、不同资源寿命或独立调度的场景不要
强行串成一条旅程。独立场景不共享可变数据库。说明合并后的诊断与调度代价，不把少几个绿点
当作收益。纯格式表可汇总错误；依赖前序成功的流程应在失败处停止，不强行继续污染后续证据。

只删除被覆盖的重复证明或已明确退出的契约。删掉独有边界不是“精简”；批量 ignore、放宽断言、
吞掉错误、自动重试、隐藏失败都不是替代方案。改测试名或组织后，检查过滤表达式、feature 配置
和必要的 catalog 集合完整性；零用例不能当作已验证。没有证据就保留并列出待核对项。

## 断言与样本

期望应来自明确契约或独立样本，不调用同一个被测算法生成期望。序列化往返可能编码、解码同错，
需要时增加独立预期或负例；仅比较 ID、长度、`is_ok()`、`is_object()` 不等于验证完整业务结果。
fixture 的字段级断言、负例和错误语义不能在合并时悄悄丢失。静态样本的值不应变成生产硬编码。

样本只需足够触发目标：分页要有下一页和尾页，过滤要有不匹配项，删除要先证明待删事实存在，
回滚要读回确认没有部分写入。页边界、跨记录关联和附件大小边界不因缩小规模而消失。

性质／模型测试适合纯状态和有界命令序列：限制 case 与序列预算，保留 seed 和最小反例，模型
不得复刻实现。无需为数个简单边界引入框架；不要把整库初始化放进每个生成样本里。

## 生命周期、隔离与成本

先删除重复执行，再缩小 fixture，最后考虑复用准备成果。nextest 默认每个测试独立进程，
`OnceCell`／`OnceLock` 不跨测试进程复用。共享不可变模板时，每个独立场景复制到专属目录；模板
必须绑定引擎、schema、seed 和相关 feature，并安全完成关闭／一致性快照，不能复制正在写的裸库。
初始化、迁移、冷启动和恢复测试仍直接走被测路径，不能全被模板替代。

不以固定 sleep 等待可观察事件；有合适 seam 时用通知、受控时钟或有界等待。并发契约使用独立
连接／执行者和明确同步点，不用串行 happy path 代替竞争。不要因测试便利污染生产状态机。

Docker 只作为工具链、依赖和资源边界的可选运行器，不假定已经接入，不共享活跃测试数据库。
复用现有构建锁和兼容环境的缓存；不增加任务级 target，不默认上 tmpfs 或提高并发。性能比较
区分构建、初始化、测试主体与总 wall time，并记录缓存、并发和存储条件；不可比数据不算提速率。

## 交付与持续修订

交付只需写清：改动的契约、旧到新的覆盖对应、环境／执行次数的变化、已运行和未运行的验证。
选择命令、确认实际选中用例、默认／相关 feature 分别验证及失败归因，使用 `$check`。
原始日志、计数、耗时和提交进度留在任务／CI／Git；不要复制进本 skill 变成长期门槛。

出现新的可复用发现时，先在实现或日志中核实，找出适用条件和反例，再修订最相关的旧规则或案例；
冲突时替换或收窄，不不断追加禁令。没有新证据则不改 skill。技能修改与功能改动都保留独立可审阅
diff，检查路由、引用和正反例；完成当前范围后停止，不自动扩展为全仓清理。
