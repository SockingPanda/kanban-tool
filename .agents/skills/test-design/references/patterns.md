# 测试设计案例

这些案例解释选择方法，不是新增测试配额或全仓测试库存。实现改变时回查 owner；不要仅为追随
案例重构未受影响模块。命令由 `$check` 选择，以下片段是设计示意，不是可直接运行的仓库 API。

## 同一条昂贵证明只运行一次

反例：每个记录类型各定义 producer／consumer 测试；每个入口都导出、导入、替换导入整份
富样本，内部又遍历完整 catalog。外层仅重复查看当前记录 ID。

改法：一条全目录往返契约保留跨记录关系和真实存储；格式、字段映射与负例放在无数据库的契约
中。目录校验要能识别遗漏和重复，不能仅遍历“实际剩下的条目”便报告完整覆盖。不要再加入
进程外缓存框架来保住那些没有独立价值的入口。

需要分开的反例：导入前篡改、页提交后中断、提交后重放有不同前置状态和观察点，不能因为都叫
“导入”就合并成成功旅程。当前 owner 示例可从
[Server suite](../../../../crates/kanban-server/src/suite.rs) 与
[portable 契约](../../../../crates/kanban-server/src/suite/portable_adoption.rs) 回查。

## 格式表保留独立预期与具名诊断

```text
fixture 名称 → 具体 DTO → decode → 明确字段语义 → encode → 与原 JSON 比较
```

可以用一个局部泛型 helper，返回含 fixture 名称和阶段的错误，再由一个具名契约汇总。只检查
`is_object()` 不能替代精确 JSON；合并时保留非默认字段、Unicode、数组内容和已有负例。
若 getter 会转换字段，除了 roundtrip 还要保留 getter 的独立期望。

往返不等于独立正确性：编码器与解码器可能一起错。真实路由响应、字段映射和生产者的独立 oracle
仍按所需边界保留。仅静态反序列化的测试名字不写“真实 router”。默认不为了几个 helper 新建
共用 crate，也不搬动协议文件以制造更大的依赖变更。

## 删除与分页要能抓住最简单的错误实现

删除反例：记录已由 alpha 更新为 gamma；删除后查询 alpha 为零。即便漏执行 DELETE 也通过。
有效观察：更新后 alpha 为零、gamma 存在；删除后 gamma 为零。

分页反例：只有一个对象，limit=1，只看第一页。有效最小样本要跨页，并含不匹配对象；验证精确
返回集合、下一页游标、尾页终止、无重复和遗漏。游标绑定条件的契约变化时，用已有格式／查询
测试补反例，而不是为每种 filter 再建一条完整 Host 旅程。

## 幂等与原子性不以“第二次成功”作为全部证据

同一 request 重试应读到同一业务结果，且不会重复 event、job 或附件副作用；新的冲突 request
仍需拒绝。失败后从实际存储读回，检查原事实及版本未出现不允许的部分变化。并发 claim 还要
有真正重叠的执行者与同步点；单线程重复调用只证明重试，不证明竞争原子性。

这些是不同契约，不因共用 fixture 而一律合并。检查内部 SQL 次数只有在证明明确的成本边界时
才有价值；不要将全部 SQL 的精确顺序或条数变成正常重构无法改变的约束。

## 环境复用不是状态复用

工具链与下载缓存可重复使用；独立可变数据库、连接、租约和 failpoint 不跨场景共享。确实仍有
重复初始化时，再考虑本轮生成的只读模板，并验证其与直接初始化路径一致；不拿一次缓存命中
证明首次初始化。关闭、快照和复制语义必须以实际数据库引擎为准。

先区分“重复启动流程”“少量独立但昂贵的场景”“构建或换页成本”，再决定措施。容器化、并发
调整和 fixture 改造分别比较，不从测试入口减少比例推导耗时减少比例。

## 参考依据

- [Google：Unit Testing](https://abseil.io/resources/swe-book/html/ch12.html)：以行为命名、明确断言与失败信息；重构实现不应机械改写所有测试。
- [Google：Change-Detector Tests](https://testing.googleblog.com/2015/01/testing-on-toilet-change-detector-tests.html)：避免只复制实现而缺少独立预期的测试。
- [nextest：Why process-per-test](https://nexte.st/docs/design/why-process-per-test/)：进程隔离的默认执行模型及其共享状态限制。

外部资料解释取舍，不替代当前代码契约；工具行为发生变化时重新核对官方文档。
