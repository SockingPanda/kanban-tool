# 0010 协作规则、技能路由与验证入口

状态：接受。

## 背景

仓库已有单 Host、共享 service、多入口和 owner 文档。多个 agent 可以独立实现局部功能，但迁移入口、
契约、生成物和依赖锁文件仍存在共享写入责任。协作规则需要帮助执行者恢复最小充分上下文，也要允许
程序检查规则与实际文件是否一致。

## 决定

保留现有运行时 crate 和入口，不为协作管理增加运行时服务、数据库或新的框架层。并行工作使用独立
worktree，同一共享入口由当次集成执行者协调。任务记录持有基线、归属、计划与证据；仓库只持有长期规则。

继续使用六个 repo skill。领域术语维护归现有 docs skill，根路由必须与实际提供的技能包一致。Rust
xtask 检查该闭合关系，以及根契约、技能正文和文档治理/协作指南中的显式本地引用。
检查不读取用户全局技能目录，也不执行模型或技能正文。默认由一个执行者完成实现与自验证，
独立审查仅在用户明确要求时启动，不按日期、版本或风险自动安排。

justfile 保持唯一命令入口。增加文档结构检查入口，并保留包含 rustdoc 与 doctest 的完整文档检查。
普通文档变化可以先选结构检查；公开 Rust 文档契约变化仍使用完整验证。仓库契约检查进入独立 CI，
不替代真实 Host、业务测试、完整构建或发布验证。

同机 worktree 继续共用一个已有构建锁与 target root。CI 显式选择 runner 内的统一目录，不继承个人挂载路径。

## 取舍

根文件和 skill 数量保持稳定，降低自动加载内容的体积。针对路由闭合增加少量 Rust 代码，不增加第三方
依赖。它能证明明确的结构约束，不能证明模型一定会正确遵守规则，也不能判断所有文档语义冲突。

拆分文档验证入口保留原命令含义，避免让旧 CI 突然跳过 rustdoc。轻量入口仍依赖 xtask 的编译和依赖环境，
因此只能相对完整工作区文档构建而言更窄。

本决定暂缓大规模目录重排。未来只有明确的跨层依赖、公共 API 或长期职责需要，才用独立变更调整 crate
边界；不得把“便于多 agent”直接当成拆 crate 的充分理由。

## 落点

协作流程见 [Agent 协作](../collaboration.md)，技能检查位于 xtask 的 agents checker，命令由根 justfile
持有。一次性审查报告与测试记录不进入本 ADR。
